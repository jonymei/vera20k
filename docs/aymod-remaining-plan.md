## 2. 工作方式与防止空转

每次只推进一条完整玩家可见链。先查现有 owner、活动调用与证据，再决定是否修改。
必要前置同链完成；大机制另列依赖，不能延期却关闭本链。

- 台账区分生产缺口、设计冲突、已有实现但集成未验、玩家待验和当前无消费者。
  不重写已有实现，不追加没有新判别力的微边界测试。
- 每条链先明确失败表现或缺失证据、生产入口、完成终点。未发现缺陷则更新覆盖并转下一项，
  不为得到代码改动而改正确实现，也不以孤立组件通过关闭完整功能。
- 核原始指令、活动调用和正式分层数据，原生函数名/地址留在代码旁。
  状态、RNG、计时器、Detach、换主、保存/hash及同帧后果通过既有唯一 owner。
- 有玩法修改的链提交前做一次独立只读 critic，修正发现并重跑受影响覆盖。
  可委派独立调查/审查，不并行实现多条玩法链。
- 决策阻塞只阻塞相关链，继续其他可做项；确无安全动作并满足阻塞审计后才标受阻。
